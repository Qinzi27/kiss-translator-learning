# PDF 双语阅读

阅读器左侧显示 PDF 原稿画布，右侧显示提取的原文与逐段追加的译文。支持英文与简体中文两个方向，沿用插件里已保存的翻译服务。Chrome 151+ 可直接在打开 PDF 时进入本阅读界面，默认只显示原文，点击翻译后才调用服务。

本说明对应 **2.0.35-learning.6（预发布）**；learning.4 及更早安装包不包含本版 PDF 阅读器。下文描述实现与使用方式，合成测试和构建检查不等于实机验收。开发机器已安装 Chrome 153，但新增 MIME 接管、预翻译与会话恢复的完整扩展流程尚未实测。既有 Web 预览的真实验证见文末。

## 打开阅读器与文件

**Chrome 151+ 的直接入口**

1. 打开本地 PDF 或在线 PDF。官方 MIME 接管可用且未关闭时，浏览器直接显示本版阅读器，地址栏保留原 PDF URL；无需先点击工具栏插件。
2. 文件在本机读取并显示原稿、提取原文。默认不会调用翻译服务；选择服务和方向，再点击 **翻译本页**、**一键翻译全文**，或主动开启 **翻页自动翻译**。
3. 页面中可取消勾选 **打开 PDF 时直接使用双语阅读器**，关闭之后的自动接管；点击 **返回 Chrome 原生阅读器** 可返回当前文件的原生查看器。

本版只接管顶层 PDF，不接管网页中的内嵌 PDF。它读取 Chrome 已接收的 PDF 响应流，不再次下载原地址；因此本地文件也无需另开 **允许访问文件网址**。其他浏览器是否提供相同能力，以实际 API 可用性为准。接管只是打开原文，不构成向云端发送文字的授权。见 [Chrome mimeHandler 官方文档](https://developer.chrome.com/docs/extensions/reference/api/mimeHandler)。

**旧浏览器或关闭接管后的手动入口**

浏览器中已经打开可识别的 PDF 地址时：

1. 点击浏览器工具栏的扩展图标，再点击 **翻译当前 PDF**。已有的翻译快捷键 **Alt+Q**（macOS 为 **Option+Q**）和原右键翻译命令也会识别 PDF。
2. 当前标签切换到插件自己的阅读器，自动读取文件、翻译当前页，并开启 **翻页自动翻译**。使用阅读器选中的已保存服务；服务无效或请求失败时会显示错误，不会自动换用其他服务。
3. 如果原 PDF 地址明确包含 `#page=N`，从该页开始；超过总页数时取最后一页，否则默认第一页。扩展不能读取原生查看器内部的滚动位置，因此没有页码片段时不能保证接续你正在看的那一页。

这条手动入口的自动读取和翻译，只接受上述扩展操作生成的、绑定当前标签的一次性 `storage.session` 授权。普通外部链接或手动添加的 `#url=…` 只能预填地址，不会因此下载或发送文字；浏览器不提供此会话能力时也退回预填流程。更换文件不会继承之前的自动翻译授权。

也可以从设置页的 **PDF 双语阅读** 入口打开新标签。直接点击 **选择 PDF 并翻译**，选中下载的文件后，会使用当前服务自动翻译当前页并开启翻页翻译；此文件选择方式无需开启扩展的文件网址访问权限。若只想先看原稿，使用 **打开本地 PDF**；公开 HTTPS 直链则点击 **读取链接**。这两种只读入口不自动发送文字，需要再主动开始翻译。

文件加载成功后，来源区域会折叠为 **更换 PDF / 查看来源**，保留阅读与翻译控件。通过地址打开的文件提供 **返回原 PDF ↗** 链接。

两种入口都使用插件自己的阅读器，不修改 Chrome 原生 PDF 内部控件。Chromium 的官方测试明确区分外层网页与 PDF 内部框架：内容脚本可进入外层框架，但不能进入 PDF 扩展框架或内容框架。旧版手动入口使用标签页导航，Chrome 151+ 使用正式的 MIME 接管接口。见 [Chromium PDF 内容脚本测试](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/chrome/browser/extensions/content_script_apitest.cc)和 [Chrome tabs.update 文档](https://developer.chrome.com/docs/extensions/reference/api/tabs#method-update)。

使用旧版手动入口直接读取本机 `file:///…pdf` 时，仍需为扩展开启 **允许访问文件网址**；未开启时，可以点击 **选择 PDF 并翻译** 重选文件，无需改变权限，或到扩展详情页开启权限后重新进入。直接读取路径仅支持本机文件，不支持网络共享路径。这项限制不适用于 Chrome 151+ 的官方 MIME 流入口。文件访问权限见 [isAllowedFileSchemeAccess](https://developer.chrome.com/docs/extensions/reference/api/extension#method-isAllowedFileSchemeAccess) 与[权限声明说明](https://developer.chrome.com/docs/extensions/develop/concepts/declare-permissions)。阅读 PDF 本身不需要启动 Python 阅读服务；使用 Argos 翻译仍需准备下文的本机推理服务。

源码开发预览启动后，可访问 `http://127.0.0.1:4318/pdf.html`；预览启动方式见[项目首页](../README.md)。网页预览可检查手动读取与翻译，但没有 Chrome MIME 处理框架或扩展标签页授权，不能替代扩展环境验收。油猴版本暂不支持此入口。

手动粘贴的公开链接应直接返回 PDF。插件主动下载不携带网站 cookies、API Key 或来源页 referrer，也不跟随 HTTP 重定向；需要登录、订阅权限或跳转的地址可能失败。可在有访问权限的网站正常下载文件，再通过 **打开本地 PDF** 读取。官方 MIME 入口读取的是浏览器原本已获准打开的响应流，不能绕过网站访问限制。

## 阅读、翻译与切换服务

- **翻译本页**：优先处理当前页，同时开启翻页自动翻译并预翻译后两页；命中缓存的段落不重复请求。页面边缘的浮动翻译按钮使用相同行为。
- **翻页自动翻译**：开启时优先处理当前页，并预翻译后两页，最多并发 2 个请求。翻页重排待处理任务，保留已在途请求，避免转到预取页时重复发送；完成的结果仍写回对应页。命中相同文件、服务配置与语言方向缓存的段落不重复发送。预翻译同样会消耗服务额度，可以取消勾选以关闭。
- **一键翻译全文**：退出翻页自动翻译模式，优先当前页，再处理其余页；命中缓存的段落跳过请求。
- **停止**：停止后续处理、关闭翻页自动翻译，并保留已经显示的译文。已发送的单次请求可能仍在服务端完成；停止不代表撤回服务方已收到的文字。服务出错同样会关闭自动翻页模式，不会自动回退到其他服务。
- **切换服务或语言**：保留旧译文并标记其服务与方向，不立即发送新请求。需要主动重新翻译当前页；若仍勾选翻页自动翻译，下一次翻页会使用新服务和语言。成功的段落逐一替换，失败或停止时，尚未替换的旧译文仍保留。
- **分页与原稿**：使用上一页、下一页或页码选择框；可收起原稿，只看右侧原文与译文。

加载或翻译期间，服务、语言和新文件选择会暂时禁用；需要更换时先点击 **停止**。翻译期间仍可翻页，待处理队列随之调整优先顺序，已在途请求不会仅因翻页而丢弃。停止或打开另一份文件会取消当前任务，迟到结果不会写入新文档。仅打开另一份文件时会关闭自动翻译；**选择 PDF 并翻译** 则明确授权对新选文件开始翻译。

已完成译文使用专用会话缓存，按文件、服务配置和翻译方向区分；合计最多 **80 页、8 MiB**，按 LRU 淘汰最近最少使用的内容。超限、浏览器会话结束或存储不可用时，不能保证保留全部译文。刷新后重新读取同一文件可恢复仍在缓存中的结果，**不会自动续发翻译或预翻译**。手动选择的文件不能在刷新后直接重读，需要再次选择同一文件才能命中缓存。

已安装扩展使用 `storage.session`，浏览器会话结束时清除；只刷新阅读器不等于结束会话。Web 预览使用 `sessionStorage`，浏览器恢复标签时可能保留，不能视为同等清除保证。关闭缓存所在的预览标签或清除其站点数据会影响恢复。

当前阅读器显示结果也有独立的 80 页、8 MiB 内容上限，优先保留正在看的页面，超限淘汰较旧结果；这不是整台浏览器的内存上限。单段服务译文最多 16,000 个 JavaScript 字符长度计数，超过时停止该轮翻译并保留旧译文，不静默截断。

新增或编辑服务后，点击 **刷新服务设置**。每次开始翻译也会重新读取所选服务的最新配置；禁用或已删除的服务会报错，不会自动换成其他服务。本阅读器不修改全局网页翻译规则。

MyMemory 是无需 Key 的在线限量接口；AI 服务可能需要自己的 Key、已开通模型或付费额度。配置方法与服务边界见 [AI 翻译服务说明](../AI-SERVICES.md)。全文翻译会逐段产生请求，开源阅读器不意味着接口无限免费。

## 本地解析与离线翻译

文件解析、画布绘制和文字提取使用随包附带的 PDF.js 资源，在本机进行。官方 MIME 接管、**打开本地 PDF** 或 **读取链接** 不会自动发起翻译；选择 **选择 PDF 并翻译**、点击翻译、主动开启翻页翻译，或使用 **翻译当前 PDF** 等扩展命令授权后，待译段落才会发送给所选服务。**翻译本页** 同样会开启翻页模式，发送后两页中尚未命中缓存的段落。选择云端服务仍会联网，服务方可能留存文本。

阅读器关闭通用持久翻译缓存与跨文档 AI 对话上下文，已完成译文只使用上述专用会话缓存。它不会把整个 PDF 文件自动上传给翻译服务；会话缓存仍含阅读内容，不是加密保险库。这些本机存储规则不限制服务商自身的记录行为。私人 PDF 和用户会话数据不作为公开发布附件。

使用 Argos 离线翻译前，需要在本机完成以下准备：

1. 先联网安装 Python 依赖、下载并预热中英模型，运行离线推理验证。
2. 启动本机 Argos 服务，并将本机生成的配对令牌填入扩展 Argos 服务的 **Key**，保存配置。不要手动添加 `Bearer ` 前缀。
3. 在设置中选择 **仅本机离线** 联网策略，回到 PDF 阅读器点击 **刷新服务设置**，选择 **本机离线 · Argos**。
4. 打开提前保存的本地 PDF，再点击翻译。保持 Argos 服务运行。

完整步骤、Windows 命令、令牌与模型迁移说明见 [Argos 首次准备与离线使用](../offline/README.md)。扩展包和源码包不内嵌已下载模型或 Python 虚拟环境；换电脑需要重新准备。

联网策略约束插件主动发出的 PDF 链接下载和翻译请求。**仅本机离线** 会阻止插件重新下载远程 PDF 及调用云端翻译；**屏蔽谷歌** 可以继续使用非谷歌服务。官方 MIME 入口读取 Chrome 已提供的流，不控制或撤回浏览器此前打开 PDF 的网络请求。切换策略不会把云模型变成本地模型，也不控制网页自身或其他软件联网。

本次 PDF 开发验证尚未重新完成 Argos 离线 PDF 翻译。已有 Argos 合成文本和网页的离线记录，不能代替这条新增流程的验收。

## 文件与版面限制

| 项目           | 当前上限或行为                                                 |
| -------------- | -------------------------------------------------------------- |
| 文件大小       | 非空，最多 50 MiB（52,428,800 字节；界面简写为 50 MB）         |
| 页数           | 最多 200 页                                                    |
| 全文提取文字   | 最多 2,000,000 个字符长度计数，按 JavaScript UTF-16 长度累计   |
| 每页文字流条目 | 最多 20,000 个 item                                            |
| 全文文字流条目 | 最多 300,000 个 item                                           |
| 下载与解析等待 | 下载最多 45 秒；整份文件解析、提取最多 90 秒                   |
| 翻页预翻译     | 当前页优先，后两页预取，最多并发 2 个请求                      |
| 会话译文缓存   | LRU，合计最多 80 页、8 MiB                                     |
| 当前阅读器结果 | 独立限制为 80 页、8 MiB 内容；单段译文最多 16,000 字符长度计数 |

item 是 PDF 内部的文字流条目，不等于一段文字；同一句话可能包含很多条目，空文本条目也会计入复杂度上限。文件过大、过长或过于复杂时，请先拆分。需要密码的 PDF 应先在有权使用的阅读器中解锁并另存副本。

当前没有 OCR：扫描件或只有图片的页面可能显示原稿，但右侧没有文字。可先使用 OCR 工具生成带文字层的 PDF，再打开。

段落顺序由文字坐标推断，适合常见横排单栏及部分双栏文档。复杂分栏、旋转或竖排文字、浮动图注、跨页段落、表格和数学公式可能拆散、重排或被当作普通文字翻译，请始终对照原稿。为适配接口长度限制，长段落还会分片，可能影响上下文和语句连贯性。

**当前不导出保持版式的译文 PDF，也不提供译文 PDF 下载。** 左侧保留的是原文件的页面外观；右侧是便于阅读的原文与译文，不会把译文写回原 PDF。

## 开源组件与安全边界

阅读器使用 [Mozilla PDF.js 6.3.289](https://github.com/mozilla/pdf.js/releases/tag/v6.3.289) 的官方 `legacy` 兼容构建，主库与 worker 固定为同一版本。`legacy` 用于补齐较旧浏览器缺少的 JavaScript 特性，没有回退到旧版 PDF.js。PDF.js 主库遵循 [Apache-2.0 许可证](https://github.com/mozilla/pdf.js/blob/v6.3.289/LICENSE)，保留 Mozilla / PDF.js 贡献者归属；本学习分支自身继续遵循 [GPL-3.0](../LICENSE)。

随包附带的字体、CMap、ICC 与解码资源还各有许可证，不能统一标为 Apache-2.0。尤其本版本的 [Liberation 字体](https://github.com/mozilla/pdf.js/blob/v6.3.289/external/standard_fonts/LICENSE_LIBERATION) 使用 GPLv2 加字体例外及附加条款，[Foxit 字体](https://github.com/mozilla/pdf.js/blob/v6.3.289/external/standard_fonts/LICENSE_FOXIT) 保留 PDFium Authors 的许可条件。构建会保留 `pdfjs/LICENSE` 及各资源目录中的 `LICENSE*`；再分发时应一并保留。

当前仅使用 PDF.js 的页面解析、画布渲染和文字流提取，不启用 PDF 脚本管理器或 XFA，不加载 `pdf.sandbox` / QuickJS；WASM 使用关闭，扩展维持默认 CSP，不为 PDF 放开字符串脚本执行。文件内容和译文作为文本显示。解析具有限额、取消、超时和 worker 释放机制，但这些不等于已经证明能防御所有恶意文件。
